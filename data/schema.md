# Dataset and model schema

Two generated artefacts back the app:

| File | Generated by | Consumed by | Size |
| --- | --- | --- | --- |
| `data/manifest.json` | `scripts/convert-fc26.mjs` | `lib/info.ts` (static import) | ~1 KB |
| `public/data/players.json` | `scripts/convert-fc26.mjs` | `lib/dataset.ts` (runtime fetch) | 3.5 MB |
| `data/model.json` | `scripts/fit-model.mjs` | `lib/model.ts` (static import) | ~90 KB |

`manifest.json` and `model.json` are small enough to bundle. The player payload
is **not** — it is fetched once at runtime and cached in a module-level
`Map`, with a streaming reader reporting download progress to the loader UI.

## Regenerating

```bash
npm run data:generate   # CSV -> manifest.json + public/data/players.json
npm run data:model      # players.json -> data/model.json
```

The converter reads the source CSV from a path constant at the top of
`scripts/convert-fc26.mjs`. Point it at your export and re-run.

## Player payload

`public/data/players.json` is **columnar**: one flat array per field rather
than one object per player. 17,347 players × 33 attributes is 572,451 numbers;
as objects that JSON is roughly twice the size and far slower to parse.

```
{
  n: 17347,
  attributes:      string[33]   // attribute key order, shared by every row
  groupAttributes: string[6]    // "pace","shooting","passing","dribbling","defending","physic"
  dictionaries:    { positions[12], nations[158], leagues[43], clubs[663] }

  // Parallel arrays, all length n. Dictionary-coded fields hold integer
  // indices, not strings.
  ids, names, shortNames, pos, alt, age, nat, lg, cl,
  height, weight, foot, weakFoot, skillMoves,
  ovr, potential, valueEur, wageEur, reputation

  attr:  number[n * 33]   // row-major: row i starts at i * 33
  group: number[n * 6]    // EA's published group ratings
}
```

`lib/dataset.ts#hydrate` turns this into `Player` objects, decoding every
dictionary index, and builds the percentile tables.

### Why columnar

- ~40% smaller than the equivalent nested JSON.
- `attr` becomes 33 typed-array-friendly columns, so a percentile lookup is a
  binary search over a sorted `Int16Array` rather than a scan across 17k objects.

### Gotchas

- **Dictionary indices, not strings.** `pos[0] === 4` means `positions[4]`. Forgetting
  to decode renders every position as a bare integer.
- **`alt` is `number[][]`**, not `number[]` — a list of alternative positions,
  empty for most players.
- **`foot` is not dictionary-coded**: `1 = Left`, `0 = Right`. Verified against
  the source (`"Left"` for Saka, Lamine Yamal; `"Right"` for Mbappé, Vinícius).
- **Attribute order is load-bearing.** `attr` rows are positional, so
  `attributes[i]` must stay the key for column `i`. `ATTRIBUTE_KEYS` in
  `lib/types.ts` and the converter's column order must agree; the typecheck
  does not catch a mismatch, only a data assertion will.
- **Goalkeepers have no group ratings.** All 2,062 GK rows in the source carry
  `0` across all six, not a missing value. `Player.hasGroupRatings` is `false`
  for them and every group-rating surface checks it. Never render
  `player.groups.PAC` unguarded.

## Model

`data/model.json` holds two independent ridge regressions, because the overall
formula is not position-independent:

| Segment | n | Features | CV R² | CV MAE | alpha |
| --- | --- | --- | --- | --- | --- |
| outfield | 15,512 | 33 | 0.9141 | 1.385 | 0.3 |
| goalkeepers | 1,835 | 33 | 0.9977 | 0.275 | 3 |

Each segment carries standardisation (`mean`/`std`), a coefficient per feature,
a per-position intercept, cross-validated and in-sample metrics, baselines, the
alpha sweep, and out-of-fold residuals.

Prediction is `positionIntercept + Σ coef · (x − mean) / std`.

Two properties the UI depends on:

1. **The model is linear in the attributes**, so `contributions` sums to
   `value − baseline` exactly. That identity is what makes the attribution
   charts and the What-If Lab arithmetic rather than simulation.
2. **Coefficients can be negative** — 10 of 33 for outfielders, 16 of 33 for
   goalkeepers. That is collinearity, not EA penalising an attribute: pace and
   passing move together across a squad, so ridge splits a shared signal
   between them.

### Honest ceiling

Outfield CV R² is 0.9141. EA's position eligibility flags and attribute × position
interactions were both tested and neither moved R² (`model.diagnostics`). The
attributes are in the file; the position weighting that turns them into an
overall is not published. Goalkeepers — whose formula is not position-dependent
— are reconstructed to ±0.28, which is the control confirming the outfield gap
is informational rather than algorithmic. Do not present this as a reverse-
engineered EA formula.

### Group ratings

`model.groupValidation` records our attempt to reconstruct EA's six group ratings
as a weighted average of member attributes. Pace and defending reproduce;
shooting does not. The app therefore uses the published `group` column verbatim
and never derives it. This is why `PlayerCard` reads `groups` rather than
recomputing from `attributes`.

## Provenance

The bundled dataset is the real FC 26 export supplied for this project, not
generated. `synthetic` is `false` throughout, and the UI's synthetic-data
banner is driven by that flag rather than hard-coded.

Rows are filtered to `overall >= 55` (`minOverall`), which drops 18,405 → 17,347.
The threshold exists because the per-attribute columns and the model are only
meaningful for players a user would actually look up; the unfiltered tail adds
~1,058 rows of noise to the dataset and nothing to the interface.

Names are cleaned at conversion time: the export glues the Latin name onto the
player's name in their own script with no separator on 1,341 rows, which
`cleanName()` strips. See `NAME_OVERRIDES` in `scripts/convert-fc26.mjs` for the
hand-corrected cases.

Portraits are **not** in the payload. They are served by `/api/face/[id]`, which
rebuilds the CDN path from the numeric id, so shipping 17,347 ~50-character URLs
would add roughly 900 KB to a payload nothing reads. Set
`NEXT_PUBLIC_USE_FACES=false` to fall back to the procedural silhouette.
